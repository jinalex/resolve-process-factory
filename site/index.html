Turn natural language business rules into formal logic

Resolve turns an operations team's standard operating procedure (SOP), the written steps people follow, into rules a solver can check. The SOP owner settles what the solver flags. Then an agent gathers each case's facts, the rules decide, and Resolve names any fact still missing.

The demo uses a Know Your Business (KYB) procedure: how a bank confirms who owns a company before opening its account.

Install the Claude Code mod

In Claude Code, Resolve is a pane beside the chat. It shows the rules' open questions for the SOP owner, every case's outcome and case file, and a button to approve a version.

Option 1: install the mod (one step)

Open in Claude Code desktop Open in Claude Code CLI

Each button opens Claude Code with the install typed in; press Enter to run it. The CLI link works once you have used claude in a terminal at least once. Or paste the command yourself:

/plugin install resolve --marketplace jinalex/resolve-process-factory

Start a new session in an empty folder and the pane opens beside the chat. Press Set up the real run and Claude fetches the repo and gets the pane ready, in about 2 minutes with no API key. It needs git, Node 22.23.4 or later and pnpm. Until then the pane shows a sample run. /resolve opens it again.

Option 2: check out first

To clone it yourself instead, check out the repo, then install the mod as in Option 1 and start a new session in that folder. It needs Node 22.23.4 or later and pnpm; pnpm start runs Resolve's checks and writes a question for each finding into .resolve/.

git clone https://github.com/jinalex/resolve-process-factory
cd resolve-process-factory && pnpm install
pnpm start

No API key is needed. The questions for the KYB SOP's first version come from saved replies, and anything new is asked through Claude Code on your own sign-in. A key in RESOLVE_ANTHROPIC_API_KEY or ANTHROPIC_API_KEY is used instead when one is set.

More from a checkout

Run these in the checkout from the install steps above. Only the case runner and the bench need an API key (RESOLVE_ANTHROPIC_API_KEY or ANTHROPIC_API_KEY).

pnpm test            # outcomes, Z3's checks, Z3 agreeing with the evaluator
pnpm examples        # each example case's outcome and why
pnpm check-sop       # Z3's findings on the KYB SOP
pnpm start           # checks, then the SOP owner's questions, into .resolve/ for the pane
pnpm resolve         # the checks alone, into .resolve/
pnpm write-options   # Claude writes the SOP owner's questions
pnpm next-spec       # the SOP owner's answers become the next version

A public regulation: the FTC Telemarketing Sales RuleReal. On 51 LegalBench cases, Resolve decided 28 and got 27 right; Opus alone got the same 27 of those 28. Resolve sent the other 23 to review, including the 2 violations Opus alone called compliant, and never called a case compliant. The 28 rely on five scope facts we supply.

The KYB SOP, its cases and the answer key were written for this prototype. The answer key is the SOP's approved rules.

Code, SOPs, specs and design notes: github.com/jinalex/resolve-process-factory The bank in the SOP is fictional. Its section 3 follows the US beneficial-ownership rule (FinCEN's customer due diligence rule, 31 CFR 1010.230).
